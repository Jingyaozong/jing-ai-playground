> 本文依据荆提供的方法整理，扩展表达待荆确认。文中的小例子完全虚构，只用于解释判断过程，不是实际项目的脱敏复刻，也不是已验证的模型问题。

Bad Case 不是一筐“坏样本”。它需要回答：哪里不符合要求、依据是什么、可能是哪一层出了问题、改变以后怎样验证。

## 先分类，再统计

图像任务可以先分为指令不匹配、主体偏移、结构异常、细节失真、美学问题、清晰度问题。视频任务可沿用 [八维评测框架](/notes/video-evaluation-eight-dimensions/) 做主分类，再细分异常。

分类规则应说明每类定义、正反例、边界以及允许多标签与否。保留样本 ID、来源、批次、规则版本、任务类型和严重度，再统计问题数量与占比。

三个数不要混淆：

- 样本失败率：至少一个不合格问题的去重样本数 / 本轮有效评测样本数。
- 某类发生率：出现该类问题的去重样本数 / 对该类适用且实际评测的样本数。
- 错误构成比：某类问题记录数 / 全部问题记录数；统计单位是记录，不是样本。

多标签发生率相加可能超过 100%。分批、分来源、分人员分析时，要同时看任务难度、分配量和抽检方式；未经校正的错误数量不能直接当人员能力排名。定向抽取的高风险问题也不能混进随机抽检率。

## 原因分成五层

| 原因假设 | 先找什么证据 | 可能的处理 |
| --- | --- | --- |
| 数据本身 | 输入损坏、错配、重复、信息不足 | 修复关联、隔离无效数据或重新采样 |
| 标签与规则 | 定义冲突、边界缺失、版本不一致 | 补正反例、裁决边界、修订版本 |
| 执行理解 | 明确规则下仍出现重复误判 | 定向培训、复标、复考 |
| 工具与流程 | 导入映射、保存、导出或状态流转异常 | 修复流程并回查受影响批次 |
| 模型能力 | 排除输入与评测流程问题后仍可复现 | 建专项集，交算法侧验证能力缺口 |

这是排查方向，不是五选一的自动结论。同一个问题可以有多个原因；证据不够就保留“待确认”，不要见到坏输出就写“模型能力不足”。

## 一个虚构的小例子

独立虚构的图像任务要求：“桌上放两个绿色纸风车。”假设评测记录写着“数量错误”，但展示缩略图只看到一个。

先打开完整输入与输出，确认第二个是否被裁切；再查文件与 Prompt 是否配对正确。如果规则没说清被遮挡主体怎样计数，需要先裁决规则。只有在文件、关联和规则都确认后，才能讨论输出是否真的漏生成。

这段推演没有实际图片，也没有执行结果。它说明的是：**一个表面现象，可以来自不同层的问题。**

## 闭环怎样结束

1. 记录问题：保存证据、期望、观察和影响，不改写原记录。
2. 分析原因：为假设补验证动作，明确谁负责确认。
3. 修改材料：数据、规范或流程分别留变更记录，标明受影响范围。
4. 团队同步：讲清新旧规则差异，以针对性例题确认理解。
5. 重新验证：复查已知错误，并检查同类新样本是否再次出现。

“已改”与“已验证”是两个状态。失败样本重跑成功，只证明这些样本的修复情况；检查新增但同类的保留样本，才有助于判断是否只是记住旧题。

```text
现象标签 / 严重度 / 证据：待填

修改对象 / 版本 / 影响范围：待填

复验样本 / 条件 / 结果：待执行
残留问题 / 关闭依据：待确认
```

## 从问题到补数据

从模型目标出发定义能力。图像描述（本文简称 IC）可检查主体、属性、动作、关系、OCR 和幻觉；视觉问答（VQA）可检查识别、计数、空间、文本理解和推理。缩写与标签名称在具体项目中需先对齐。

按业务分布抽样，同时保留长尾、边界和高风险样本。高频错误可以组成专项集，但专项集与代表业务分布的标准集分开报告，不能用大量简单样本稀释难题。

评测与训练去重不只比较 ID，还需关注同源图、近重复内容和派生版本。参考答案经过适当专家复核，保留难度、场景与错误标签。开放答案允许同义归一化，但不能把否定、数量或空间关系的变化归成同义；不可回答题须有明确判法。

固定 Benchmark 保留纵向比较的核心题，新发现的问题另建增量专项集。进入训练的数据应与保留评测部分隔离，避免将后续训练过的旧题继续称为独立测试。

## 建议写到可执行

数据优化建议至少写清“能力缺口、证据样本、拟补场景、质量规则、去重要求、验证方式”。不要只写“多补一些高质量数据”。

例如，虚构纸风车任务如果最终确认是遮挡条件下的计数缺口，可以提出分层构造遮挡程度与数量组合的候选方案。但补多少、是否有效，仍需真实执行后验证；本文不预设改善幅度。

方法可以在 [六阶段虚构标注演练](/notes/synthetic-annotation-delivery/) 中串起来：试标暴露问题，规则修订后再放量，交付时保留首检与复检的不同记录。
