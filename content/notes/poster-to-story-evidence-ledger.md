一张虚构海报已经很像一个故事：异常天空、空荡站台、亮着灯的旧电影院，或者晴天街道旁只在室内落下的雪。看见这些画面时，人会立刻补上人物、原因、过去和结局。

问题是，**补得合理不等于画面已经证明。** 如果把联想全部写成“海报里有什么”，故事也许很顺，却无法解释哪一部分来自输入，哪一部分来自类型惯例，哪一部分才是创作者真正做出的选择。

这篇笔记使用一个简单的来源账本，把反推过程拆成三层：

```text
E / EVIDENCE    画面中能直接指出的可见证据
I / INFERENCE   由证据支持、但仍不确定的合理推测
C / CHOICE      创作者为了让故事成立而主动加入的设定
```

> [!KEY POINT]
> 海报负责提供矛盾与线索，不负责替世界规则和人物过去背书。先标明来源，再开始创作，故事反而更容易做出真正的选择。

## 为什么“直接看图写故事”不够

本站的 [EXP.008 海报反推故事实验](/experiments/can-a-fictional-poster-grow-a-story/)固定使用三张 AI 生成的无片名海报：双月公交站、退潮电影院、室内落雪的失物招领处。每张图分别使用三种路径，各保留一次未经人工修订的文本：

| 路径 | 操作方式 | 首轮页面编辑初审 |
| --- | --- | --- |
| A / 直接反推 | 看图后直接输出人物、规则、冲突与梗概 | 综合均值 3.33 / 5；成稿快，但三次边界透明均为 1 / 5 |
| B / 证据优先 | 先列可见线索，再进入故事 | 综合均值 4.67 / 5；线索利用清楚，但推测与主动设定仍混在一起 |
| C / 三栏反推 | 分开写证据、推测和主动选择 | 综合均值 4.75 / 5；三次边界透明均为 5 / 5，同时三次出现“解释过量” |

这九份样本不能证明某种方法普遍更好。它们只说明了一个值得继续验证的方向：**直接写容易越过来源边界，完整三栏又可能挤占故事空间。** 因此下一步不是保留最长说明，而是把 B 的简洁证据清单与 C 的来源透明合并成一份短账本。

## E：只记录别人也能指认的东西

`E / EVIDENCE` 不是画面解读，而是观察记录。一条合格证据应该能回答：“如果把图放在两个人面前，他们能否大致指出同一个位置？”

可以从六类线索开始：

| 线索 | 可以写 | 暂时不要写 |
| --- | --- | --- |
| 主体 | 一座旧电影院；一个空站牌；柜台后没有人 | 电影院已经废弃多年 |
| 环境 | 潮湿滩涂；晴天街道；室内积雪 | 海水正在吞没城市 |
| 异常 | 天空出现两个月亮；雪只落在门内 | 另一个月亮来自平行世界 |
| 空间关系 | 建筑四周有浅水；门内外天气不同 | 门是两个时代的入口 |
| 光线 | 入口透出暖光；天空明亮 | 暖光代表有人等待主人公 |
| 道具 | 红围巾、行李箱、电影灯箱 | 围巾属于失踪的妹妹 |

证据不需要华丽。它的任务是给后面的推测和选择留下可以追溯的编号。

```text
E1. 一座旧电影院孤立在潮湿的滩涂上。
E2. 入口向外透出暖黄色灯光。
E3. 建筑四周有浅水和倒影。
E4. 远处能看见海平线。
E5. 画面里没有人物、车辆或邻近建筑。
E6. 天空明亮，处于白天。
```

如果看不清，就写“无法确认”。模糊的招牌不能自动变成片名，像人影的形状也不能直接获得身份。

## I：允许推测，但必须保留“不确定”

`I / INFERENCE` 负责把零散线索连成可能的解释。它比观察多走一步，但还没有成为世界事实。

每条推测最好同时具备两样东西：

1. 使用“可能”“也许”或其他不确定措辞；
2. 标出它依赖的 E 编号。

```text
I1. 建筑可能只能在退潮时进入。（依据：E1、E3、E4）
I2. 暖光也许说明内部仍有能源。（依据：E2）
```

这一步的意义不是让语言变得谨慎，而是防止故事在没有意识到的时候被第一种联想锁死。`I1` 也可以有别的解释：建筑也许正在被潮水隔离，或者水面只是极端天气后的积水。保留不确定性，创作者才有选择空间。

推测最多保留三条。超过这个数量，账本很容易变成逐像素解读，故事还没开始，前置说明已经占满注意力。

## C：把“我决定这样写”说清楚

`C / CHOICE` 不是错误，也不是需要隐藏的东西。人物身份、世界规则、异常原因、交换代价与结局，大多都必须由创作者主动加入。

关键是承认它来自创作，并说明它怎样使用现有证据。

```text
C1. 影院只放映下一次风暴潮到来前的二十分钟。（回应：E2、E3、E4）
C2. 预警只有在影院被永久注销后才能带走。（回应：E1、E2）
C3. 主人公是负责关闭这座建筑的工程师。（回应：E1、E5）
```

这三条不是海报事实。它们之所以比“这里藏着一个神秘老人”更有用，是因为每条都改变了故事结构：谁必须进入、能获得什么、需要付出什么，以及为什么不能转身离开。

> [!BAD CASE]
> “电影院很神秘，所以主人公进入后发现一个惊天秘密。”这句话没有明确世界规则、限制或代价。它借用了海报气氛，却没有把视觉线索变成因果。

## 从画面矛盾长出故事发动机

账本不是最终成品。它应该继续压缩成一条能推动故事的因果链：

```text
可见矛盾
  ↓
世界规则
  ↓
规则制造的限制
  ↓
主人公的当下任务
  ↓
无法同时保住的两件事
  ↓
不可逆选择
```

以退潮电影院为例：

| 层级 | 一种待开发写法 |
| --- | --- |
| 可见矛盾 | 白天、无人滩涂上的旧影院仍从入口透出暖光 |
| 世界规则 | 影院只在退潮时开放，并放映下一次风暴潮前二十分钟 |
| 限制 | 预警不能复制；只有永久注销影院才能带出放映内容 |
| 主人公任务 | 负责关闭危险建筑的工程师必须在涨潮前完成注销 |
| 两难 | 保留唯一能持续预警的影院，或带走这一次能救人的撤离信息 |
| 不可逆选择 | 她签下拆除令，带走撤离路线，让影院随涨潮永久消失 |

这仍然只是编辑示例，不是已经完成的故事。它展示的是每一层怎样使用前一层，而不是要求所有海报都变成灾难寓言。

## 三个问题，检查设定是不是类型套壳

一个设定可以很精彩，也可能与输入毫无关系。完成 C 栏以后，连续问三次：

### 1. 删除海报后，故事还能原样成立吗

如果把电影院换成灯塔、车站或废弃仓库，人物、规则、冲突和结局都不需要变化，说明海报只是封面装饰。

### 2. 至少三条证据是否进入了因果

“出现过”不等于“被使用”。浅水、暖光和无人环境需要改变进入条件、时间限制或人物决策，而不只是被梗概重新描述一遍。

### 3. 世界规则是否真的迫使人物选择

规则不能只是“这里会发生奇怪的事”。它需要制造成本：只能进入一次、不能同时带走两样东西、每次使用都会失去一段记忆，或者救一个人就会关闭另一个出口。

## 账本和梗概不要互相重复

三栏方法在首轮 Pilot 中最清楚，也最容易出现解释过量。解决办法不是删掉来源边界，而是让账本和故事承担不同工作：

- 账本使用短句，最多 `6 + 3 + 3` 条；
- 梗概不再解释 E、I、C 的定义；
- 梗概从人物已经面临任务的时刻开始；
- 自检只保留使用的 E 编号、最大主动设定和最可能落入的套路；
- 详细审计另存，不塞进最终故事正文。

因此同一份输入最好导出三份不同文件：

1. **短证据账本**：保存来源边界；
2. **故事任务卡**：定义片名、人物、规则、冲突、选择和梗概；
3. **完整 Prompt**：把前两份内容交给支持图片输入的模型。

[海报反推故事组装器](/tools/poster-story-builder/)已经把这三份输出做成浏览器本地工具。它不会上传图片，也不会调用模型，只负责整理当前填写的来源链。

## 什么情况下不要使用这套方法

E／I／C 适合从单张视觉输入发展故事，但不是所有创作都需要它。

- 已有完整剧本时，应该检查海报是否准确表达故事，而不是反过来重写故事；
- 需要自由联想时，可以先写，再回头标注来源，不必让账本打断第一稿；
- 海报只是情绪参考时，不需要强迫每个颜色和道具承担剧情功能；
- 画面包含真实人物、地点、品牌或历史事件时，不能用合理推测替代事实核查；
- 需要判断模型能力时，必须固定模型、版本、上下文和评分方法，单篇好故事不能代替对照实验。

## 一次可复用的反推流程

```text
01 先看图，不写故事
02 记录最多 6 条 E，不补全看不清的部分
03 写最多 3 条 I，每条标记证据编号
04 写最多 3 条 C，说明它回应哪些证据
05 用 C 建立世界规则、限制与人物任务
06 让冲突逼出一次不可逆选择
07 写 150—250 字梗概，不重复账本
08 检查至少 3 条 E 是否进入因果
09 保存原始输出，润色版另存
```

## 交付前最后检查

- [ ] E 栏只包含能从画面直接指出的事实；
- [ ] 模糊信息被标成“无法确认”，没有自动补全；
- [ ] 每条 I 都保留不确定措辞，并标出依据；
- [ ] 人物身份、异常原因与世界规则来自 C，而不是伪装成画面事实；
- [ ] C 栏不是随意套用的类型桥段；
- [ ] 世界规则制造了真实限制；
- [ ] 限制迫使主人公在两项代价之间选择；
- [ ] 至少三条证据参与因果，而不只是重复出现；
- [ ] 去掉这张海报以后，故事不能原样成立；
- [ ] 原始文本、评分与后续改写已经分开保存。

**创作不需要假装自己只是“发现”了一个藏在画面里的故事。** 更诚实也更有用的做法，是保存画面给出的起点，标明推测走了多远，再对真正决定加入的设定负责。
