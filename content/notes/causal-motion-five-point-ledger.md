“她撑开伞，随后水面退去”读起来有明确先后。到了视频里，两个动作却可能同时发生：伞还在展开，水线已经移动；水先退了一小段，伞才锁住；或者水线先退、再回弹，最后仍然抵达正确终点。

只看第一帧和最后一帧，这些错误都可能被漏掉。因果动作需要检查的不是“两个状态有没有出现”，而是：**动作 A 是否已经完成并保持，动作 B 才第一次发生变化。**

```text
ACTION A          HOLD              ACTION B
开始 → 完成 → 锁定 ───────────────→ 首动 → 单向变化 → 终点
                ↑                  ↑
             A 锁定帧           B 首动帧
```

> [!KEY POINT]
> “随后”不是一句气氛描述，而是一个可以失败的时间条件：B 的首动帧必须严格晚于 A 的锁定帧，中间还要留下看得见的稳定状态。

## 先把一个镜头拆成两条轨道

因果动作卡不先写长 Prompt，而是分别填写 A 与 B。两条轨道回答不同问题：

| 轨道 | 必须写清 | 不够清楚的写法 |
| --- | --- | --- |
| 动作 A | 起点、完成状态、锁定时刻、锁定以后必须保持什么 | “她把伞打开” |
| 动作 B | 启动前状态、首动时刻、唯一方向、可验收终点 | “水自然退去” |
| 人物与道具 | 身份、手位、数量、接触关系 | “人物保持一致” |
| 摄影机 | 固定或移动、景别、构图、焦段 | “电影感镜头” |
| 环境常量 | 坐标、材质、光线和不能跟着变化的物体 | “背景不要乱” |

以《退水以前》Shot 11 的**待测试计划**为例：动作 A 是红伞从合拢到完全展开并锁定；动作 B 是斜水线从画面左前方连续退向右后方出口。书架、书页、木地板、人物站位和摄影机都属于保持项。

这不是视频观察。当前 [EXP.010](/experiments/can-water-recede-after-the-umbrella-opens/) 仍是 `0 / 9`，没有真实样本可供填写锁定帧或首动帧。

## 因果闸门只有一个硬条件

设动作 A 的锁定帧为 `F_A`，动作 B 的首动帧为 `F_B`：

```text
可测试：F_B > F_A
不可测试：F_B ≤ F_A
```

“大于”只是最低条件。两个时间点只差一帧时，观察者可能无法确认 A 是否真的稳定，因此还需要记录可见间隔：

```text
可见间隔 = F_B - F_A
```

间隔没有脱离模型、帧率和动作类型的通用合格数字。本站工具会在间隔过窄时提醒复核，但不会把提醒冒充模型能力结论。真正执行时，应把多个间隔作为实验变量，而不是先宣布某一个数字最好。

> [!BAD CASE]
> 如果 A 设为 70% 才锁定，B 却设为 20% 首动，这不是“有风险的 Prompt”，而是一份顺序自相矛盾的任务。应先停止导出，修正时序，再进入生成。

## 为什么选五个时间点

五点账本记录 `0 / 25 / 50 / 75 / 100%`。它不是完整逐帧分析的替代品，而是一张低成本路线图：

| 检查点 | 动作 A 要回答什么 | 动作 B 要回答什么 |
| ---: | --- | --- |
| 0% | 起点是否正确 | 起点、边界和坐标是否清楚 |
| 25% | 正在变化，还是已经锁定 | 是否仍完全保持 |
| 50% | 是否已经完成并稳定 | 是否保持，或刚到允许首动的边界 |
| 75% | 锁定状态是否漂移 | 是否沿唯一方向推进 |
| 100% | 是否仍保持完成状态 | 是否到达终点且没有回弹 |

这五点能快速发现三类问题：B 提前启动、B 的路径不是单调变化、A 在 B 运动时发生漂移。发现异常以后，再回到异常前后的真实帧逐帧定位。

## 计划帧号不是实际帧号

水线动作卡会把百分比换算成计划参考。以 6 秒、24 fps 为例，总长度约为 144 帧，五个边界位置显示为 `F0 / F36 / F72 / F108 / F144`。

这里的 `F144` 是 100% 时间边界，不等于所有剪辑软件都存在一个零基编号为 144 的画面。不同播放器可能显示 `0—143`、`1—144`、时间码或抽帧后的代理编号。

因此生成以后必须重新记录：

```text
播放器或剪辑软件：
帧编号约定：零基 / 一基 / 时间码
实际 A 锁定帧：
实际 B 首动帧：
首次失败时间：
```

计划值负责定义任务，实际值才负责描述结果。两者不能混写。

## 完整 Prompt 要保留一段停顿

一份可执行的因果动作 Prompt 至少包含六段：

1. `0%`：A 与 B 的起点；
2. A 从起点变化到完成，B 保持；
3. A 到达锁定状态；
4. A 保持锁定，B 继续静止，留下可见停顿；
5. B 从固定起点沿唯一方向变化，A 与环境保持；
6. `100%`：A 仍锁定，B 到达可验收终点。

```prompt
先让动作 A 从起点完成到锁定状态；动作 B 在此期间完全保持。
动作 A 锁定后保留一段可见停顿。
停顿结束以后，动作 A、人物、摄影机和背景继续保持，
只让动作 B 从固定起点沿唯一方向连续移动到固定终点。
单个连续镜头，不使用切镜或遮挡跳过中间动作。
STATUS: 待测试 Prompt，不代表已经生成或通过。
```

这段文字是结构示例，不是某个视频模型的最佳语法。不同平台仍需根据当前模式、参考图和官方说明调整。

## 负面约束要对应可见失败

禁止项不是通用质量词堆栈。它应该来自这条因果链最可能出现的报废现象：

| 失败标签 | 实际要找的画面现象 |
| --- | --- |
| `EARLY_START` | B 在 A 锁定以前已经发生位移 |
| `SIMULTANEOUS` | A 与 B 的主要变化区间重叠 |
| `ORDER_REVERSED` | B 先动，A 后完成 |
| `ACTION_DRIFT` | B 启动以后，A 的完成状态继续变化 |
| `PATH_REVERSE` | B 曾向终点移动，又回到早先位置 |
| `PATH_SPLIT` | 一个边界分成多条或局部随机消失 |
| `WORLD_DRIFT` | 背景、道具、光线或人物跟着 B 一起改变 |
| `HIDDEN_CUT` | 用切镜、遮挡或画面重置跳过因果交接 |

标签的作用是让九个候选使用同一种记录语言。没有真实视频时，只保留空表，不能提前替候选勾选“通过”。

## 生成后怎样逐帧验收

一次完整验收可以按这个顺序进行：

### 1. 先找 A 的实际锁定帧

从 A 接近完成的位置逐帧查看。只有当 A 到达目标状态，并在后续帧里不再继续变化，才能记录为锁定。

### 2. 再找 B 的第一次可见变化

从 B 的起点向后比较。第一次能可靠指出边界、位置或形状已经变化的帧，才是首动帧。压缩噪声、反光闪烁和整幅画面抖动需要与真实位移区分。

### 3. 比较顺序和间隔

检查 `F_B > F_A`，再记录中间稳定了多少帧。不要因为结尾正确，就忽略开头已经抢跑。

### 4. 核对五点位置是否单调

把五个检查点并排看。B 应持续接近同一个终点，不能在 75% 时比 50% 更靠近起点。

### 5. 检查保持项

A、人物、道具数量、接触关系、摄影机、背景结构、材质与光线方向都需要单独核对。B 成功移动，不代表整镜通过。

## 哪些任务适合这套方法

它适合两个阶段之间必须存在清楚先后的单镜任务：

- 手完全握住杯柄以后，杯子才离开桌面；
- 门锁扣合以后，走廊灯才依次熄灭；
- 人物停稳以后，局部雨区才开始扩散；
- 红伞完全锁定以后，水线才沿固定方向退去。

如果两个动作本来就应该同时发生，例如人物推门时门同步旋转，就不应强行加入停顿。那类任务需要检查接触与同步，而不是因果闸门。

## 从计划到结论，中间不能跳步

```text
填写两条轨道
  ↓
检查 A 锁定 < B 首动
  ↓
导出五点账本、Prompt 与空白验收表
  ↓
生成并保存真实候选
  ↓
记录实际帧号与失败标签
  ↓
完成九格以后再写阶段结论
```
