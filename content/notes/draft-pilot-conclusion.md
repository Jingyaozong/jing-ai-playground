一项工作只要出现在网页上，就很容易显得“已经完成”。标题、封面、排版和编号会自动给内容增加确定感，但页面看起来完整，不等于背后的工作真的走完了。

这次整理 JING AI PLAYGROUND 时，最重要的动作不是增加更多案例，而是重新标明：**哪些已经发生，哪些只是计划，哪些有少量样本，哪些还不能形成结论。**

> [!KEY POINT]
> 状态不是装饰标签。它决定访客应该把一段内容当作创作方向、过程记录、可复查证据，还是已经成立的判断。

## 先建立一条不会跳级的状态链

一项创作或实验可以沿着下面的顺序推进，但不应该因为页面做得漂亮就跳过中间环节。

| 状态 | 已经拥有 | 还不能声称 |
| --- | --- | --- |
| 概念候选 | 一个问题、设定或值得保留的方向 | 已进入制作、已有样本、已经验证 |
| 创作草案 | 剧本、分镜、Prompt、流程或计划文档 | 已生成成片、制作完成、效果成立 |
| Pilot 小样 | 少量真实输出和初步记录 | 代表完整测试、证明稳定规律、支持模型排名 |
| 正式实验 | 预先定义的问题、变量、样本和记录规则 | 在样本未完成时提前宣布结果 |
| 可发布结论 | 完整样本、条件、观察记录、失败项与适用范围 | 把局部结果写成永久规律或普遍能力 |

这里的关键不是所有项目都必须做成论文，而是**文字的确定程度不能超过证据的完成程度**。

## 草案回答“准备怎么做”

本站 Story 001《[她每天醒来都会忘记昨天](/stories/she-forgets-yesterday/)》已经拥有故事设定、六场剧本、十四镜分镜、人物锚点和逐镜生成包。这些都是已经存在、可以打开检查的工作。

但它仍然是创作草案，因为目前：

- 没有真实视频模型输出；
- 没有剪辑、声音和成片；
- 没有三镜动作测试结果；
- 人物名字、对白语气和结尾判断仍待荆确认。

因此准确的写法是“剧本与分镜已整理，真实视频尚未生成”，而不是“第一部 AI 短片制作完成”。草案的价值没有因此降低：它证明制作准备已经推进到哪里，也清楚暴露下一步缺什么。

> [!TIP]
> 描述草案时，尽量同时写出“已有内容”和“未完成内容”。只写“制作中”太模糊，访客无法判断它停在一句想法、完整剧本，还是等待剪辑。

## Pilot 回答“这套办法值得继续测试吗”

Experiment 001《[同一个她，四十个镜头](/experiments/forty-shots-one-character/)》的目标，是观察同一角色在景别、光线、情绪和动作变化中怎样保持一致。

现在页面上有一张四格静态人物板。这四格是真实存在的 AI 生成视觉，可以帮助检查人物锚点是否清楚、页面记录结构是否可用，也能让下一轮测试更具体。

但四格静态图不能替代四十个视频镜头。它没有覆盖：

1. 动作过程中的身份变化；
2. 遮挡前后的连续性；
3. 人体和物体互动；
4. 摄影机运动与主体运动；
5. 不同视频模型和生成参数。

所以它被标记为 **Pilot 4 / 40**，而不是“实验完成”。Pilot 的任务是降低正式实验的启动成本，不是提前生产结论。

## 正式实验回答“在固定条件下发生了什么”

当 Pilot 暴露出需要验证的问题，才进入正式实验。至少要在生成以前写清楚：

| 项目 | 应该留下什么 |
| --- | --- |
| 实验问题 | 这次只想回答哪一个问题 |
| 假设 | 预期会发生什么，并明确它尚未被证明 |
| 控制变量 | 哪些输入、参考图、时长和参数保持不变 |
| 改变变量 | 每组究竟改变景别、光线、动作还是模型 |
| 样本计划 | 计划多少条，实际完成多少条，失败或缺失多少条 |
| 观察规则 | 用什么字段、评分锚点和失败标签记录 |
| 原始结果 | 每个样本的文件、参数、观察原句和处理决定 |

实验执行以前，“假设”不能改名叫“发现”；样本没有填完以前，“观察方法”不能写成“实验结果”。

```text
问题：变量增加时，哪些身份锚点最先失去一致性？
假设：遮挡和大幅度转身可能比静态景别变化更容易造成漂移。
当前证据：四格静态 Pilot，不包含动作或遮挡测试。
下一步：先生成三个五秒高风险镜头，再决定是否扩展到四十镜。
```

上面的“可能”必须保留。它是一条待验证假设，不是模型已经表现出的规律。

## 观察、解释和结论是三句话

即使已经拿到样本，也不要把看到的现象直接写成原因。

- **观察**：镜头 07 在人物经过遮挡后，右侧蓝色发夹消失；
- **解释假设**：遮挡可能削弱了参考图中配饰锚点的持续约束；
- **结论**：只有在保持其他条件不变、重复测试后，才能判断遮挡是否稳定提高该失败的出现率。

观察描述画面里发生了什么；解释提出可能原因；结论说明证据支持到哪里。把三者写在不同字段里，可以防止一次偶然输出被包装成稳定能力判断。

> [!BAD CASE]
> “四十镜以后，角色最先忘记的是耳环”听起来像一个有趣发现，但在四十镜尚未生成时，它只能是一句虚构结果。没有样本编号、条件和记录，就不应该出现在实验卡片上。

## 资料来源和个人观点也要分层

同样的规则适用于收藏系统。Library 里的原始链接已经逐条核对，所以可以写“来源已核对”；推荐理由和 JING&apos;S TAKE 多数仍是编辑初稿，所以必须写“待荆确认”。

这四类文字应该分开：

1. **来源事实**：标题、作者、发布机构、链接和公开内容；
2. **内容摘要**：对来源信息的压缩，不添加来源没有表达的结论；
3. **编辑推荐理由**：解释为什么暂时把它放进这座网站；
4. **个人观点**：只有荆确认或补写之后，才以荆的口吻发布。

来源真实，不会自动让附在旁边的个人观点也变成真实。

## 发布以前，用五个问题做最后检查

每次把新故事、实验或笔记放进网站前，检查：

1. 页面声称存在的文件、样本或步骤，真的可以找到吗？
2. 状态名称是否比实际进度更确定？
3. 是否把计划日期、样本数量或测试结果写成了已经发生的事实？
4. 观察、解释假设和结论是否被混在同一句话里？
5. 用户个人观点是否经过本人确认，还是仍属于编辑初稿？

如果第五题答案是否定的，不需要删除整篇内容。更诚实的处理方式是明确写出“编辑稿 · 待确认”，同时保留真实来源、工作过程和下一步。

## 这套方法现在也有边界

这篇文章来自一次真实的网站内容校准，但它还不是经过多轮项目验证的通用规范。状态链能帮助当前网站减少误导，是否适合荆未来所有创作流程，还要等待真实视频生成、实验复盘和长期维护来检验。

> [!JING'S NOTE]
> 待荆确认：以后每个项目是否都采用“概念候选 → 创作草案 → Pilot → 正式实验 → 可发布结论”这套状态链，以及哪些阶段可以合并。

当前可以确定的是：**未完成并不可怕，模糊地假装完成才会让作品失去可信度。**
