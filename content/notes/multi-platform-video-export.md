横版完成以后再点一次“自动重构为 9:16”，看起来像是多平台发布的最后一步。真正打开成片时却经常出现另一种结果：人物被切掉一半，字幕被界面盖住，原本靠左右关系成立的反打失去意义，十五秒短版只剩一段没有结论的开场。

问题不是导出按钮，而是把“另一个发布版本”误认为“同一支片的另一个尺寸”。

> [!KEY POINT]
> 多平台拆版不是把一个时间线输出成多个分辨率。每个发布位置都应有自己的画幅、时长、观看情境、字幕、安全区、声音和验收记录；母版负责保存最高质量，发布版负责适配具体观看方式。

## 先区分母版与发布版

母版不是最先上传的文件，而是后续版本能够回到的干净源头。它通常保留完整画面、稳定的时间线、最高可用质量，以及可单独处理的字幕和声音素材。

发布版则是为一个明确位置制作的派生文件。它至少回答：

| 问题 | 要记录的内容 |
| --- | --- |
| 在哪里播放 | 具体平台、页面、播放器或广告位置 |
| 画面怎样出现 | 横屏、竖屏、方形、列表缩略图或全屏信息流 |
| 允许多长 | 当前账号和发布入口显示的时长要求 |
| 什么会遮挡画面 | 标题、头像、按钮、描述、进度条和系统手势区域 |
| 字幕怎样交付 | 烧录、外挂文件、平台自动字幕或多语言版本 |
| 声音怎样使用 | 默认有声、可能静音、对白优先或需要音乐授权 |
| 谁确认过规则 | 官方页面、核对日期和测试账号 |

把这些内容写成发布矩阵，比记住一串“通用最佳尺寸”可靠。平台会更新界面、分类方式和上传限制，同一平台的不同入口也可能使用不同规则。

## 不要给视频主动加黑边

[YouTube 的官方画幅说明](https://support.google.com/youtube/answer/6375112)指出，播放器会根据视频与设备适配不同画幅；它也建议不要把 padding 或黑边直接做进视频，因为这会影响播放器动态适配。

这给多平台母版一个简单原则：**保留原生画幅，让播放器处理播放器的边，让创作者处理内容的构图。**

如果必须交付一个固定画布，应把“加边”记录为某个发布版本的明确要求，而不是永久烙进母版。否则下一个播放器再适配一次时，可能出现双重边框或更小的有效画面。

## 先算几何损失，再做视觉判断

从 16:9 中心裁成 9:16，会保留原画面中间的一小段宽度。这个几何结果可以计算，但不能直接告诉你画面是否可用。

```text
当母版比目标画幅更宽：
横向保留比例 = 目标宽高比 ÷ 母版宽高比

当母版比目标画幅更高：
纵向保留比例 = 母版宽高比 ÷ 目标宽高比
```

几何保留比例只适合做预警。真正的裁切判断还要看：

- 主体是否一直位于同一侧；
- 人物是否在镜头内移动；
- 两个人是否靠横向距离建立关系；
- 文字、手机屏幕和关键道具是否靠近边缘；
- 运镜是否会让主体离开竖版裁切框；
- 景别变紧后，动作是否仍然读得懂。

因此发布矩阵可以写“中心裁切预计保留 32%”，但不能据此写“竖版可用”。后者必须逐镜检查。

## 三种拆版动作

### 1. 同构输出

目标画幅与母版接近，主体和文字都位于安全范围内，可以保留同一剪辑，只调整导出规格。这是成本最低的一类。

### 2. 动态重构

目标画幅变化明显，但原镜头仍有足够分辨率和构图空间。可以逐镜调整水平位置、缩放或关键帧，让裁切框跟随主体。

动态重构不是给整条时间线套一个自动跟踪。每个镜头的构图意图不同：近景可能跟眼睛，双人镜头可能需要保留关系，道具特写则要跟手与物体的交互。

### 3. 重新剪辑或补镜

当关键关系本来就依赖宽画幅，或目标版本的时长明显更短，仅靠裁切无法解决。需要重新选择镜头、改变顺序、补充特写，甚至生成专门的竖版镜头。

> [!TIP]
> 判断是否重剪的快速方法：关掉声音和字幕，只看裁切后的画面。如果观众无法判断“谁在做什么、为什么要看下一镜”，问题已经不是分辨率，而是叙事版本。

## 短版不能只从结尾剪掉

四十八秒母版变成十五秒版本，不等于删除最后三十三秒。短版需要重新分配镜头职责。

可以先把母版镜头分成四类：

| 镜头职责 | 短版处理 |
| --- | --- |
| 建立情境 | 保留一个最短但可理解的线索 |
| 提出问题 | 尽早出现，避免观众不知道在看什么 |
| 推进与变化 | 只保留能改变理解的动作或信息 |
| 回报或悬念 | 短版也需要一个完整落点，而不是突然结束 |

重新剪辑后再处理字幕与音乐。直接把完整旁白加速，或者删掉停顿而不调整声音结构，通常会让短版只剩信息密度，没有节奏。

## 安全区要从真实界面反推

竖屏满画幅并不等于所有像素都能承载关键信息。平台界面可能在顶部、底部或侧边覆盖头像、标题、互动按钮和系统区域。

[Meta 的 Reels 广告官方页面](https://www.facebook.com/business/ads/facebook-instagram-reels-ads)明确强调 9:16、声音和关键元素位于安全区，并提供安全区检查资源。[TikTok for Business 的创意质量检查表](https://ads.tiktok.com/business/library/Top_Tips_One_Pager_SMB.pdf)同样把全屏 9:16、规格与安全区列为发布前检查项。

这不意味着所有竖版都可以共用一组永久安全区数值。更稳妥的做法是：

1. 在发布当天打开目标入口；
2. 查看最新官方模板或帮助页；
3. 把上下左右边距写入本次发布矩阵；
4. 在剪辑软件中建立对应参考框；
5. 用私密、草稿或测试发布查看真实设备界面；
6. 记录核对日期和入口名称。

安全区优先保护人物眼睛、字幕、产品或道具名称、关键动作和必须读到的文字。背景纹理、装饰粒子和非关键空间可以允许被覆盖。

## 字幕不是最后统一烧一次

同一套字幕在横版和竖版中的合适行长不同。横版可以容纳更长的单行，竖版如果继续使用相同字号和断句，可能出现三四行堆叠，挡住人物动作。

每个发布版应分别确认：

- 单行最大字数与断句；
- 字幕最多占几行；
- 人物说话时字幕是否挡脸或挡手；
- 字幕位置是否避开界面按钮；
- 是否同时保留无字版和外挂字幕；
- 自动字幕是否需要人工校对；
- 双语字幕是否必须拆成另一个版本。

如果画面里本身包含手机消息、信件或 UI 文字，还要把它们视为构图元素，而不是字幕。竖版裁切后可能需要重新排版或做局部特写。

## 声音也属于发布矩阵

Meta 的 Reels 页面把声音列入原生竖屏创意要求；TikTok 的官方检查表则要求确认音乐、旁白或两者混合时的可听性。这些建议提醒我们：多平台输出不是只检查画面。

每个版本至少写清：

- 交付声道和文件内是否包含声音；
- 对白、音乐、环境声谁是优先层；
- 缩短版本后音乐节拍与结尾是否完整；
- 可能静音观看时，画面与字幕能否独立传递信息；
- 音乐与素材授权是否覆盖这个发布用途；
- 上传以后是否进行了真实设备实听。

不要把某个固定响度数字当成所有平台的永久答案。记录本次交付采用的测量标准、工具和核对日期，并在最终编码文件上复测。

## 一张可执行的发布矩阵

```text
母版
- 项目与版本：
- 分辨率 / 比例：
- 时长 / 帧率：
- 不可丢失的视觉焦点：
- 字幕源 / 无字版：

发布版本
- 版本名称：
- 具体发布位置：
- 目标宽高与比例：
- 当前时长上限：
- 预计裁切方向：
- 需要重排的镜头：
- 安全区 上 / 右 / 下 / 左：
- 字幕方式：
- 音频要求：
- 文件名后缀：
- 官方规则链接：
- 最后核对日期：
- 私密测试结果：
```

矩阵里最重要的字段不是分辨率，而是“具体发布位置”和“最后核对日期”。没有这两个字段，所谓平台规格很可能只是从旧截图、其他入口或别人的账号条件复制而来。

## 发布前做三轮验收

### 文件验收

确认文件可以完整播放，开头与结尾无黑帧，画面尺寸、帧率、字幕和音轨与矩阵一致。不要只检查剪辑工程里的时间线。

### 内容验收

逐镜查看裁切后的主体、文字、道具、动作和字幕；重新判断短版是否仍有完整的提出、推进与落点。

### 平台验收

用真实发布入口上传测试，在目标手机和桌面设备查看封面、画面、字幕、音量、界面遮挡与分类结果。确认后把平台生成的链接、发布时间和最终文件校验值写回交付记录。

## 母版稳定，发布版可以继续变化

多平台工作流的目标不是一次做出永远正确的十二个尺寸，而是建立可重复的拆版关系：母版保持干净和可追溯，平台要求在发布当天核对，几何裁切先预警，逐镜重构解决真实构图，短版重新安排叙事，字幕和声音分别验收。

这样平台规则变化时，不需要重新寻找散落的工程和素材；只要回到母版，更新发布矩阵，再生成新的派生版本。
