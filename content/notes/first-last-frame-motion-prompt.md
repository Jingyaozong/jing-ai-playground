首帧和尾帧不是两张“参考氛围图”。它们分别提出两个明确要求：**镜头从哪里开始，镜头必须在哪里结束。** 运动提示词则要回答更难的问题：从起点到终点，中间到底发生什么。

只把两张好看的图交给模型，不能自动得到合理动作；只写一段很长的 Prompt，也不能修复互相矛盾的起点和终点。更可控的顺序是：先检查两端是否属于同一个可完成的镜头，再描述主体、摄影机和环境怎样共同抵达终点。

> [!KEY POINT]
> 首帧负责“现在是什么状态”，尾帧负责“最后要到什么状态”，运动提示词负责“变化如何发生”。三者不要重复抢同一项控制，也不要互相否定。

## 先用一张表分配责任

| 输入 | 主要负责 | 最容易被误用成 |
| --- | --- | --- |
| 首帧 | 初始构图、主体状态、光线、色彩、服装与空间关系 | 一张只追求氛围、但动作起点不清楚的海报 |
| 尾帧 | 结束构图、动作结果、最终视线与镜头停点 | 让模型自动理解全部转场逻辑 |
| 运动提示词 | 主体动作、环境变化、摄影机运动、速度、顺序和时间进展 | 再描述一遍首帧里已经看见的内容 |
| 产品控制项 | 景别、角度、运镜、运动参考、风格或种子等特定控制 | 默认所有平台、模型和模式都能同时使用 |

[Runway 的图生视频指南](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)把输入图视为视频的第一帧：构图、主体、光线和风格已经由图片提供，文字更应该集中描述运动、摄影机和时间进展。

[Google Cloud 的 Veo 文档](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/generate-videos-from-first-and-last-frames)则明确提供首帧与尾帧输入，并同时保留文字 Prompt 来引导生成。这说明“给了两张图”与“说明中间怎样发生”是两件不同的事。

## 什么时候只用首帧，什么时候加尾帧

不是每一镜都需要首尾两端。控制越多，模型需要同时满足的条件也越多。

### 只用首帧

适合终点不需要精确落位、重点是观察自然动作的镜头，例如：

- 人物从静止到缓慢抬眼；
- 固定镜头里窗帘和头发被风轻轻带动；
- 摄影机从中景做一次幅度不大的推近；
- 让模型自由决定动作末端，但保持人物和场景稳定。

此时首帧给出“她是谁、站在哪里、画面长什么样”，Prompt 只需要把最重要的运动说清楚。

### 首帧加尾帧

适合结束状态必须进入下一镜、必须停在某个构图，或需要明确完成一次可见变化的镜头，例如：

- 手从桌边移动到信封上，最后准确按住信封；
- 人物从背对摄影机转到三分之二侧脸；
- 空镜从关闭的门开始，以人物出现在门缝后结束；
- 本镜尾帧将直接成为下一段视频的起始画面。

尾帧增加的是**终点约束**，不是“效果增强开关”。如果结束构图不重要，让模型在更少约束下完成一个简单动作，往往更便于判断问题来自哪里。

### 不要使用尾帧的情况

- 两端人物不像同一个人，配饰、服装或发型已经变化；
- 光线方向、时间或空间结构完全不同，却没有足够时长完成变化；
- 首帧是近景，尾帧突然变成远距离俯拍，同时还要求复杂表演；
- 尾帧只是一张更漂亮的图，并不是本镜真正需要的结束状态；
- 仍在测试基础人物动作或基础运镜，还没有建立单变量基线。

## 首帧：不是海报，是动作真正开始的那一刻

好看的静态图未必是好首帧。首帧需要同时承担视觉母版和动作起点，因此要检查：

1. **动作能否从这里开始。** 手、脚、身体重心和视线是否给下一步留下空间；
2. **画框是否允许目标运镜。** 横移需要左右空间，拉远需要模型补出画外环境，环绕需要推断遮挡和背面；
3. **关键细节是否干净。** Runway 提醒，输入图中的模糊脸部、手部或其他瑕疵，进入视频后可能被进一步放大；
4. **画面有没有暗示相反运动。** 例如飞扬尘土、强烈运动模糊和前倾奔跑姿态，都可能与“人物完全静止”发生冲突；
5. **裁切与目标比例是否一致。** 平台自动裁切可能改变人物位置和镜头空间，生成前应查看实际预览。

> [!BAD CASE]
> 首帧里人物已经迈出右脚，Prompt 却要求她先向后退一步；画面里的身体重心和文字指令从第一帧就开始打架。

## 尾帧：定义结果，不替模型编写过程

尾帧最有价值的部分，是把模糊的“最后有点悲伤”变成可以核对的结束状态：人物最终看向哪里、手停在哪里、摄影机停在哪个景别、下一镜从哪里衔接。

但是首尾都正确，不等于中间过程正确。模型仍要补出每一帧的姿态、遮挡、空间和物理变化。两个端点之间的差异越大，需要发明的中间内容越多。

可以用“变化预算”预检尾帧：

| 首尾之间改变什么 | 风险较低的起点 | 风险上升的情况 |
| --- | --- | --- |
| 表情 | 中性到轻微反应 | 短时间内从平静到夸张哭喊 |
| 姿态 | 抬眼、转头、抬手 | 坐姿直接变奔跑、身体大幅旋转 |
| 摄影机 | 小幅推拉、轻微横移 | 近景跳到鸟瞰、快速完整环绕 |
| 场景 | 局部光影或天气变化 | 室内直接变室外、空间结构重建 |
| 角色身份 | 保持服装、发型和配饰 | 两端参考本身已经不一致 |

这里的“风险”不是模型能力排名，而是制作上的排错难度：变量越多，失败后越难判断应该换参考图、改动作、加时长，还是拆镜。

## 运动提示词：只写时间里发生的事

Runway 的官方指南把图生视频运动拆成主体动作、环境运动、摄影机运动、运动质感与时间、方向与速度。实际写作时，可以压缩成三个层次：

```prompt
[摄影机怎样动，或明确保持固定]
[主体从什么状态开始，经过什么动作，在哪里结束]
[环境如何响应；速度、先后和停留时间]
```

例如，假设首帧已经给出“短发女性坐在桌前、手放在信封旁”，尾帧给出“她的手按住信封、目光看向窗外”，可以先写成：

```prompt
摄影机保持固定。
她先低头看向信封，右手缓慢移动并按住信封边缘，随后才抬眼看向画外左侧。
薄窗帘轻微摆动；动作克制、连续，最后在抬眼后的静止状态停留片刻。
```

这是一条**待测试模板**，不是已经成功生成的结果。它有四个可验收点：摄影机是否固定、手是否先动、视线是否后变、尾部是否真的停住。

## 首尾帧模式下，Prompt 最重要的是“桥”

[Adobe Firefly 的图生视频说明](https://helpx.adobe.com/firefly/web/work-with-audio-and-video/work-with-video/generate-videos-using-images.html)指出，在首尾帧都提供时，文字可以帮助引导两端之间更平滑的过渡。这个“桥”至少要写清三件事：

### 1. 变化顺序

```prompt
她先松开手指，然后缓慢转身，最后在门口停下。
```

不要只列“松手、转身、走到门口”。顺序词把动作从清单变成时间。

### 2. 中间姿态

```prompt
她在转身时保持双脚原地，肩膀先转，头部随后跟上。
```

尾帧只能告诉模型最终朝向，不能说明身体应该怎样经过中间角度。

### 3. 结束前的减速与停留

```prompt
动作在最后一秒逐渐减慢，摄影机停在尾帧构图，不再继续推进。
```

如果没有结束状态，模型可能“经过”尾帧，而不是在尾帧落稳。

## 不要让四种控制同时争夺摄影机

不同产品会为景别、角度、运镜、运动参考和首尾帧提供独立控件，但它们不一定能够叠加。[Adobe Firefly 视频编辑器文档](https://helpx.adobe.com/firefly/web/firefly-video-editor/generate-videos/generate-video-using-firefly-models.html)说明，加入首帧或尾帧后，构图参考、运动参考、景别、角度或风格中的部分选项可能自动关闭；其图生视频页面还说明，加入尾帧后运镜选项也可能被关闭。

因此每次生成前都要记录本轮实际生效的是：

```text
模型 / 版本：
生成模式：仅首帧 / 首帧 + 尾帧 / 其他
首帧文件：
尾帧文件：
文字 Prompt：
界面中仍可用的运动、景别、角度或参考控件：
时长与画幅：
```

这不是为了保存操作过程给别人看，而是为了让下一次迭代知道真正改变了哪个条件。

## 三种常见冲突，先改哪一个

### 画面与文字冲突

症状：首帧有强烈向右运动线索，Prompt 要求主体向左慢慢移动。

先改：首帧。图片提供的可见事实通常比抽象文字更强；清除运动模糊、尘土和不合适姿态，再测试同一 Prompt。

### 首帧与尾帧冲突

症状：配饰换边、服装变色、场景门窗结构不同，生成过程中出现融化、跳变或无意义遮挡。

先改：两张关键帧。让角色身份、画幅、场景结构和光线方向先对齐，再讨论中间动作。

### 动作与时长冲突

症状：动作被压缩、突然切镜，或者还没抵达尾帧就结束。

先改：任务复杂度。Runway 提醒复杂动作顺序要与片段时长匹配；优先删减动作或拆成两镜，再考虑增加时长。

## 把长动作拆成连续镜头

如果一段动作无法在单个短片段里稳定完成，可以把上一段的最后一帧提取出来，作为下一段的首帧。Runway 官方指南也提供了这种延长序列的方法。

```text
镜头 A：首帧 A → 动作 1 → 尾帧 / 衔接帧 B
镜头 B：首帧 B → 动作 2 → 尾帧 / 衔接帧 C
镜头 C：首帧 C → 动作 3 → 最终状态 D
```

需要注意，共享帧不代表剪辑一定无缝。仍应检查：人物身份、背景结构、光线、运动方向和速度是否连续，并在剪辑软件里调整重复帧与节奏。

## 一份生成前检查表

- [ ] 首帧是动作起点，不只是漂亮画面；
- [ ] 尾帧确实是本镜需要的结束状态；
- [ ] 两端角色身份、服装、配饰和场景结构一致；
- [ ] 首尾差异能在当前时长内合理完成；
- [ ] Prompt 没有重复描述首帧，而是说明中间运动；
- [ ] 摄影机、主体和环境运动已经分开；
- [ ] 动作顺序、方向、速度和结束停点可以逐项验收；
- [ ] 已确认加入首尾帧后哪些产品控件仍然有效；
- [ ] 本轮只改变一个主要变量，失败后可以定位原因。

## 生成后不要只对比两张截图

逐帧检查至少包含四层：

1. **起点**：第一帧是否保留参考画面的关键构图和身份；
2. **过程**：动作顺序、遮挡、肢体和物理变化是否连续；
3. **终点**：结果是否真正落在目标状态，而不是短暂掠过；
4. **用途**：这段视频能否衔接前后镜头，是否值得进入剪辑。

首帧正确、尾帧正确，中间人物却换脸或手指融化，仍然不是可用镜头。端点控制让任务更明确，但最终验收对象始终是整段时间。

## 最后记住这句分工

**首帧给事实，尾帧给目标，Prompt 给过程。**

如果结果失控，先不要继续加形容词。回到三项责任里找冲突：起点是不是错了，终点是不是太远，中间是不是要求太多。把镜头重新缩小成一个能发生、能观察、能验收的变化，再开始下一轮。
