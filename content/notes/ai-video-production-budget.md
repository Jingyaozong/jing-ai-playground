一支 60 秒的 AI 短片，生成成本通常不等于“60 秒 × 某个平台单价”。成片里的 60 秒，是从更多候选里剪出来的：同一镜可能生成四次，每次返回多个版本；有些只用中间两秒；人物一致性失败以后还要重做参考图；最后可能继续做延长、口型、声音、放大和修复。

真正要估的不是成片有多长，而是：**为了得到这些可用镜头，需要生成多少批次、多少候选秒数，以及多少次有目标的返工。**

> [!KEY POINT]
> 预算的最小单位不是“整支片”，而是一个镜头批次。每个批次都应该知道：生成几个候选、每个多长、使用什么模型与规格、只验证什么问题、最多允许重做几轮。

## 为什么不能只算最终时长

假设成片需要一个 4 秒镜头。平台可能只能生成固定长度的片段，也可能一次返回多个候选。你最终采用 4 秒，不代表只购买或消耗了 4 秒算力。

至少要区分三种秒数：

| 秒数 | 含义 | 用途 |
| --- | --- | --- |
| 目标秒数 | 分镜计划给这一镜的长度 | 决定镜头职责和节奏 |
| 生成秒数 | 平台实际生成并计费的全部输出时长 | 计算直接生成成本 |
| 采用秒数 | 最终进入剪辑的源文件区间 | 观察素材产出效率 |

如果同一镜生成了 6 个 5 秒候选，最终只采用其中 3.5 秒，那么直接生成量是 30 秒，不是 3.5 秒。两者的差距不一定代表浪费：候选可能用于比较表演、动作和连续性。但如果这个差距持续扩大，就需要检查镜头任务、参考素材或生成策略是否没有收敛。

## 先建立一张“单位成本表”

平台计费方式并不统一，也会更新。预算表不要只写“某平台一次多少钱”，而要记录当日实际计费单位。

[Runway 的 Credits 官方说明](https://help.runwayml.com/hc/en-us/articles/15124877443219-How-do-credits-work)用“每生成一秒视频需要多少 Credits”说明不同工具的消耗，并明确总消耗还要乘以所选时长。它也说明订阅 Credits、额外购买 Credits 与到期规则可能不同。

[Google Cloud Vertex AI 的生成式 AI 定价页](https://cloud.google.com/vertex-ai/generative-ai/pricing#veo)把 Veo 的视频输出按秒计价，并分别列出视频和视频加音频等类型。[Veo 模型说明](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/veo/3-0-generate-001)还列出了模型支持的时长、比例、分辨率与返回数量。这些设置会共同决定一次请求产生多少可计费输出。

[Adobe 的生成 Credits 说明](https://helpx.adobe.com/creative-cloud/apps/generative-ai/generative-credits-faq.html)则按功能、模型与输出规格列出 Premium 功能的 Credits 消耗；[Firefly 视频生成说明](https://helpx.adobe.com/uk/firefly/web/work-with-audio-and-video/work-with-video/generate-videos-using-text-prompts.html)提醒不同模型可用设置不同，不同分辨率也会消耗不同数量的 Credits。

因此单位成本表至少包含：

| 字段 | 要记录什么 |
| --- | --- |
| 平台与入口 | 网页套餐、API、合作平台或企业账户 |
| 模型与版本 | 当日实际选择的模型名称或 ID |
| 计费单位 | 每秒、每次、每张、每个结果或套餐 Credits |
| 基础费率 | 当日官方页面显示的费率 |
| 输出规格 | 时长、分辨率、比例、是否包含音频 |
| 单次结果数 | 一次请求实际返回几个候选 |
| 附加项 | 参考素材、放大、延长、编辑、声音等额外消耗 |
| 币种与税费 | 结算币种、汇率日期、税费是否包含 |
| 核对日期 | 这条费率最后一次核对的时间 |

> [!WARNING]
> 不要从旧文章、截图或别人的套餐反推自己的单价。平台可能调整模型、Credits、订阅权益、队列和到期规则；正式预算应在执行当天重新打开官方定价页核对。

## 直接生成成本的基本公式

对于按输出秒数计费的批次，可以先使用：

```text
批次直接成本
= 候选数量 × 每个候选的计费秒数 × 单位秒成本
+ 本批次的参考素材、音频、放大或其他附加成本
```

对于按“每次生成”计费的平台：

```text
批次直接成本
= 请求次数 × 每次成本
+ 附加项成本
```

对于 Credits 套餐，先统一保留两套数：

```text
批次 Credits = 本批次实际消耗的 Credits
批次现金估值 = 批次 Credits × 本项目采用的 Credit 估值
```

Credit 估值不是平台固定事实。它取决于你的套餐、额外购买、过期余额和使用范围。可以选择把订阅费作为项目固定成本，也可以按当月可分配 Credits 折算；关键是整个项目使用同一种口径，不要一部分按会员费、一部分又把会员 Credits 当成免费。

## 一支片的预算应该分成六层

只记录生成平台消耗，会漏掉大量真实工作。

### 1. 开发与试验

包括风格测试、角色锚点、场景 Plate、动作可行性、首尾帧测试和小样。它们未必进入成片，但决定正式生产是否能收敛。

### 2. 正式镜头生成

包括每个镜头计划的基础候选。这里应按镜头而不是全片平均分配：简单环境镜头与多人互动、复杂动作、口型镜头不应拥有同样候选数。

### 3. 返工预留

包括身份漂移、场景错误、动作失败、连续性问题和无法组接造成的重做。返工预留不能只写一个任意百分比，最好先用 Pilot 记录不同风险镜头的真实候选与采用情况。

### 4. 选中镜头后处理

包括延长、局部编辑、去除瑕疵、稳定、插帧、放大、补帧、色彩匹配和合成。只有进入短名单或当前采用的镜头，才应默认进入高规格处理。

### 5. 声音与文字

包括对白、配音、口型、环境声、音效、音乐、混音、字幕、翻译和文字校对。生成视频自带声音不等于声音流程已经完成。

### 6. 人工与交付

包括分镜、Prompt 与参考素材准备、批次记录、筛选、剪辑、审片、返修、存储、下载、上传和多平台导出。即使是个人项目，也应该记录时间；否则只会看见 Credits，不会看见项目实际占用了多少天。

一张完整预算表可以这样组织：

| 成本层 | 直接消耗 | 人工时间 | 状态 |
| --- | ---: | ---: | --- |
| 开发与 Pilot | Credits / 现金 | 小时 | 待验证 / 已锁定 |
| 正式镜头生成 | Credits / 现金 | 小时 | 未开始 / 生成中 / 已选 |
| 返工预留 | 预算池 | 小时池 | 未动用 / 已动用 |
| 画面后处理 | Credits / 现金 | 小时 | 仅短名单 |
| 声音与字幕 | Credits / 现金 | 小时 | 草稿 / 终版 |
| 存储与交付 | 现金 | 小时 | 待交付 / 已交付 |

## 不要给所有镜头同一个“重做率”

AI 视频镜头的风险并不平均。建议在生成前把镜头按任务分组，再为每组设置不同候选计划。

| 风险组 | 常见任务 | 预算时重点确认 |
| --- | --- | --- |
| 低结构风险 | 空镜、静物、简单氛围、无身份主体 | 是否真的需要高规格模型和长时长 |
| 身份风险 | 角色近景、换角度、服装与配饰锁定 | 角色参考和可用表演能否同时成立 |
| 动作风险 | 手部交互、起身、奔跑、物体变形 | 是否应拆动作、缩短任务或使用首尾帧 |
| 连续性风险 | 反打、道具状态、同场景多机位 | 前后镜接口与场景账本是否清楚 |
| 声音风险 | 对白、口型、同步声音事件 | 画面生成与声音生成是否需要分开预算 |

预算不是给“高风险”镜头无限加钱。它首先应该触发一个问题：**这个任务是否应该拆成两个镜头，或先用更便宜的小样验证？**

## 用 Pilot 估计真实候选需求

没有历史数据时，不要假装知道“平均三次就能成功”。先选择少量代表性镜头做 Pilot：

- 一个低结构风险镜头；
- 一个角色身份镜头；
- 一个复杂动作镜头；
- 一个需要与前后镜衔接的镜头；
- 如果作品依赖对白，再加一个声音或口型镜头。

每个 Pilot 都记录生成候选数、直接成本、淘汰原因和最终可用区间。然后计算：

```text
候选可用率 = 达到最低可用标准的候选数 ÷ 总候选数

单个采用版本的历史候选量
= 该风险组总候选数 ÷ 该风险组最终采用版本数
```

这两个数只能描述这次 Pilot，不是模型的普遍成功率。镜头数量少、任务差异大时，不要给出过度精确的小数。更稳妥的做法是保留范围，并把身份、动作、连续性和声音分开。

> [!TIP]
> Pilot 的目标不是做出最漂亮的成片，而是暴露预算结构：什么镜头最容易返工、失败集中在哪一层、便宜模型能验证什么、何时必须升级模型或规格。

## 给预算设置三道闸门

### 闸门一：镜头职责没有锁定，不进入批量生成

如果镜头还在同时尝试故事、构图、人物、场景和动作，生成量很难收敛。先确定这一镜必须完成的可见任务和最低标准。

### 闸门二：参考与低成本测试没有通过，不升级规格

在能用较低成本验证构图、动作方向或参考图有效性时，不要一开始就把所有候选放到最高分辨率、最长时长或带声音模式。升级应该发生在问题已经缩小以后。

这不是保证省钱的公式。某些平台只提供固定规格，某些低成本模型与最终模型差异很大。记录每次升级前后解决了什么，才能判断分层是否适合当前项目。

### 闸门三：没有进入短名单，不做昂贵后处理

放大、延长、口型、局部编辑和精细声音处理应服务于已经通过叙事与连续性检查的候选。对一个仍可能被淘汰的镜头做完整后期，只会把选择成本变成沉没成本。

## 把返工拆成“有目标”和“无目标”

同样是重做一次，预算意义不同。

```text
有目标返工：
上一批的首要问题已经记录；下一批只修改一个主要变量。

无目标返工：
只觉得“不够好”，同时改 Prompt、参考图、模型、时长和机位，再随机比较。
```

有目标返工仍然消耗预算，但它产生了可复用信息。无目标返工让批次之间无法比较，也无法判断成本为什么增长。

可以为每个镜头设置两种上限：

1. 批次数量上限：超过以后必须停下来复盘或拆镜；
2. 直接成本上限：接近时必须决定降规格、换方法、改镜头或取消。

上限不是要求低于它就必须继续花完，而是防止在没有新信息时不断点击生成。

## 两个值得长期观察的成本指标

### 生成秒数与采用秒数

```text
素材有效产出率 = 最终采用秒数 ÷ 总生成秒数
```

它适合描述项目，不适合变成单一绩效目标。动作复杂、探索性强或需要大量表演选择的镜头，本来就可能产生更多候选。真正值得比较的是：同类风险镜头在流程调整前后有没有变化。

### 每个采用镜头的完整成本

```text
采用镜头完整成本
= 该镜头的开发分摊
+ 全部生成批次
+ 返工
+ 选中后的画面与声音处理
+ 对应人工时间
```

这个指标比“某模型每秒多少钱”更接近制作决策。一个单价较低但需要大量无目标返工的流程，完整成本未必低；一个单价较高但只在问题已经锁定后使用的流程，也未必更贵。必须用自己的项目记录验证，不能从价格表直接推断。

## 预算不是阻止尝试，而是保护真正重要的尝试

创作中的探索不可能全部预知，也不应该被一张表消灭。预算的作用是让探索有边界：风格测试有自己的池子，正式镜头有最低标准，高风险镜头有额外预留，昂贵后处理只服务于短名单，超过上限以后必须获得新信息才能继续。

最终要回答的不是“这支片花了多少 Credits”，而是：**钱花在哪个镜头、哪个阶段、哪一种问题上；哪些尝试让流程收敛，哪些只是重复点击。**

当镜头版本记录和预算表连接起来以后，下一次项目才会真正拥有自己的成本依据，而不是继续从平台单价和他人的成功次数猜测。
