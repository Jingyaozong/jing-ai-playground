文生视频和图生视频的差别，不是谁的 Prompt 更长，而是：**初始画面由谁负责，时间里的变化又由谁负责。**

文生视频没有参考画面，文字既要建立人物、空间、构图与光线，也要说明动作和摄影机。图生视频已经有一张起始画面，图片承担“这一刻长什么样”，文字更应该集中说明“这一刻接下来怎样变化”。

> [!KEY POINT]
> 先分配责任，再写 Prompt。不要把图生视频写成第二遍图片说明，也不要让文生视频只剩一个孤立动作。

## 一张表看懂责任分工

| 需要控制的内容 | 文生视频（T2V） | 图生视频（I2V） |
| --- | --- | --- |
| 主体是谁、长什么样 | 主要由文字建立 | 主要由参考图建立 |
| 场景、构图、光线和色彩 | 主要由文字建立 | 初始状态由参考图建立 |
| 主体怎样运动 | 由文字说明 | 由文字说明 |
| 环境怎样变化 | 由文字说明 | 由文字说明 |
| 摄影机怎样运动 | 由文字或产品控件说明 | 由文字或产品控件说明 |
| 动作顺序、速度和结束状态 | 由文字说明 | 由文字说明 |

Runway 的官方入门指南直接区分了两种输入：图生视频的 Prompt 不必重复描述图片内容，应把重点放在运动；文生视频则通常需要同时描述视觉和运动。Adobe Firefly 给文生视频的结构是“景别与摄影机 + 角色 + 动作 + 地点 + 美学”。Google Veo 的指南也将主体、动作、场景、摄影机、光线与风格拆成可组合的元素。

这些是产品指南，不是通用语法标准。不同模型、版本和控制面板会改变文字承担的范围；如果界面已经有独立的运镜或首尾帧控件，优先确认产品说明，再决定是否在 Prompt 中重复。

## 文生视频：先让第一帧成立，再让时间流动

文生视频 Prompt 至少要回答五个问题：镜头怎么看、谁在画面里、在哪里、发生什么、怎样结束。

```prompt
[景别、机位与摄影机运动]
[主体外观]位于[场景、时间、光线与构图]
[主体动作：起点 → 过程 → 终点]
[环境中同时发生的可见变化]
[画面风格、动作速度与需要保持的状态]
```

下面用本站故事中的一个镜头做**待测试示例**，它不是已经生成成功的记录：

```prompt
清晨室内中近景，摄影机固定。
一位齐下巴短发、右侧别着蓝色发夹的年轻女性坐在餐桌前，暖黄色晨光从左侧窗户照进来，桌面放着一封展开的手写信。
她先低头读信，呼吸短暂停住，随后缓慢抬眼看向画外右侧，手指始终压住信纸边缘。
薄窗帘轻微摆动，桌上其他物体保持静止。动作克制、连续，在她抬眼后结束。
```

这段文字没有堆叠“震撼、绝美、高级感”，而是在建立可拍摄、可观察的事实。情绪也被翻译成呼吸停顿、抬眼和手指压住信纸，而不是只写“她感到不安”。

## 图生视频：让图片负责画面，让文字负责变化

Runway 的图生视频指南将输入图片视为第一帧：构图、主体、光线和风格已经在那里，Prompt 的主要任务是描述动作、摄影机与时间进展。它给出的基础句式可以转译为：

```prompt
摄影机[怎样运动]，同时主体[做什么动作]。
[环境怎样响应或变化]。
[动作速度、先后顺序与结束状态]。
```

如果把刚才那一幕的完整起始画面作为参考图，文字可以收缩为：

```prompt
摄影机固定。她先低头读信，呼吸短暂停住，随后缓慢抬眼看向画外右侧，手指始终压住信纸边缘。
左侧窗帘只做轻微摆动，桌上物体保持静止。动作克制、连续，在她抬眼后结束。
```

| 同一个镜头 | 文生视频要补充 | 图生视频可以交给图片 |
| --- | --- | --- |
| 人物身份 | 发型、发夹、服装、年龄感 | 图片中已经可见的身份锚点 |
| 场景状态 | 餐桌、信件、窗户、晨光、构图 | 图片中已经成立的空间与光线 |
| 时间变化 | 读信、停顿、抬眼、窗帘摆动 | 仍然需要文字明确 |
| 摄影机 | 固定或具体运动 | 仍需文字或界面控件明确 |

> [!TIP]
> 图生视频不是“少写就好”，而是删掉已经被图片清楚表达的静态信息，把文字预算留给图片无法表达的时间信息。

## 参考图也在给模型下指令

一张图除了提供人物和构图，还可能暗示运动方向。运动模糊、飞扬的头发、扬起的尘土、前倾的身体姿态和画面中的方向线，都会让观看者推测“下一秒会发生什么”。Runway 的官方指南特别提醒：如果这些视觉线索和文字要求相冲突，结果可能难以控制。

例如，参考图里人物身体明显向左冲刺，却要求她“立即向右高速奔跑”；或者背景已经有强烈横向拖影，又要求“完全静止、没有任何运动”。这不一定永远失败，但已经把一次测试变成了两个相反信号的竞争。

因此选参考图时，也要检查：

- 姿势是否处在动作的合理起点；
- 视线、身体重心和衣物方向是否支持目标动作；
- 画面中有没有与目标相反的运动模糊或环境线索；
- 需要保持的手部、道具和遮挡关系是否已经清楚；
- 如果要求静镜头，构图是否给主体动作留下空间。

## 七种常见写法，为什么难以判断

### 1. 图生视频里重新描写整张图

重复内容会挤占动作信息，也可能让模型重新解释已经确定的人物或场景。只有当某个可见特征必须被持续保留时，才把它作为身份锚点简短重申。

### 2. 一个短镜头里塞进多个场景

“她起床、走出家门、坐上公交、到达办公室”是四个镜头，不是一条动作说明。先回到分镜，给每次空间或时间跳跃单独编号。

### 3. 用抽象情绪代替可见动作

“她很孤独”不能直接验收。可以改成“她停在门口，没有进屋，低头松开握着门把的手”。情绪仍然存在，但变成了镜头能观察的行为。

### 4. 主体运动和摄影机运动混在一起

“女孩跑向镜头，镜头快速后退”同时存在两个相对运动。如果这正是创作意图，就分别写清方向、速度和结束位置；如果不是，先固定其中一个变量。

### 5. 参考图和动作起点互相冲突

不要只看图片好不好看，还要看它是不是目标动作的合理第一帧。必要时先重做起始帧，而不是继续给文字加补丁。

### 6. 一次加入太多修正

Runway 和 Adobe 都建议从较简单的 Prompt 开始，再逐步添加细节。一次同时更换动作、运镜、构图和风格，即使结果变好，也无法知道是哪一项起作用。

### 7. 没有写验收目标

“更电影感”无法告诉你这次是否成功。至少提前写下一个核心动作、一个身份锚点、一个镜头要求，以及哪种错误会让素材不可用。

## 一次只改一个变量

把第一轮当作基础运动测试，而不是成片冲刺：

1. 先写一个主体动作，摄影机固定；
2. 确认动作的起点、过程和终点是否成立；
3. 保持其他内容不变，只增加一种摄影机运动；
4. 再增加一个环境变化或节奏要求；
5. 保存每轮 Prompt、模型版本、参数、日期和结果；
6. 用同一套验收项比较，而不是只凭第一印象。

如果上一轮人物没完成转身，下一轮却同时换图、换模型、加推镜和改服装，就无法判断问题来自哪里。迭代的价值不只是“多抽几次”，而是让下一次修改带来信息。

## 到底该选哪一种

| 你的当前条件 | 更适合先试 |
| --- | --- |
| 还在探索人物、场景和构图 | 文生视频，快速寻找方向 |
| 已经有满意的角色图或产品图 | 图生视频，围绕固定画面设计动作 |
| 第一帧必须精确衔接上一镜 | 图生视频或带首帧控制的流程 |
| 需要统一多镜头角色身份 | 先建立稳定参考图，再逐镜做图生视频测试 |
| 没有合格参考图，却有明确镜头概念 | 先文生视频探索，或先生成起始图 |

这不是质量排名。文生视频适合开放探索，图生视频适合把已有视觉决定带进时间；真实制作也常常在两者之间往返。

## 生成前的最后检查

- 我是在做文生视频，还是图生视频？
- 第一帧的主体、构图、光线由谁负责？
- 核心动作有没有起点、过程和终点？
- 主体运动和摄影机运动是否分开说明？
- 参考图里的运动线索是否支持文字要求？
- 这一条是否其实包含了多个镜头？
- 本轮只改变了哪个变量？
- 哪个失败会让素材直接不可用？

写完以后，可以先用[分镜整理器](/tools/shot-list-cleaner/)拆出景别、动作和运镜，再把镜头放进[十四镜故事生成包](/stories/she-forgets-yesterday/#generation-pack)逐条测试。结果回来后，再用[AI 视频评测流程](/notes/ai-video-evaluation/)记录任务完成度、连续性、物理问题和实际用途。

> [!JING'S NOTE]
> 待荆确认：Prompt 不是文学描写，也不是越长越专业。它更像一份微型拍摄指令——先决定谁负责画面，再决定这一秒以后发生什么。
