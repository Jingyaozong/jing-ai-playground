# 素材准备清单

网站里所有 `{……}` 都是等你填的占位符。填完以后页面会自动把它们换成正式文字、链接、图片或视频。
要改的文件只有两个：`app/data/profile.ts` 和 `app/data/video-case.ts`。

建议顺序：先填第 1、2 节（半小时内能完成，填完首页就可以给人看），再做第 3 节的视频。

## 1. 联系方式与简历

文件：`app/data/profile.ts`

| 占位符 | 填什么 | 说明 |
|---|---|---|
| `{邮箱}` | 求职用邮箱 | 填好后页面自动变成可点击的邮件链接 |
| `{简历 PDF 路径}` | `/resume.pdf` | 先把简历放到 `public/resume.pdf`，再填这个路径 |
| `{LinkedIn 或其他平台}` 和 `{平台主页链接}` | 平台名称和主页地址 | 可以加多条；没有就把 `links` 改成空数组 `[]` |

## 2. 真实项目数字

文件：`app/data/profile.ts`

**首页三个关键数字**（`stats`）

| 占位符 | 填什么 |
|---|---|
| `{30+ 人}` | 带过的团队规模 |
| `{+x%}` | Prompt-Image Match 指标提升幅度 |
| `{样本量}` | 累计评测 / 标注样本量 |

**四个项目**（`projects`）。每个项目的背景、任务、行动文案是按你给的要点起草的，请逐句对照真实情况修改。

| 项目 | 需要填的占位符 |
|---|---|
| AIGC 文生图评测 | `{公司 / 项目方}`、`{起止时间}`、`{我的角色}`、`{30+ 人}`、`{x% → y%}`（双人复核一致率）、`{+x%}` |
| 多模态图文匹配 / OCR（博彦科技） | `{起止时间}`、`{我的角色}`、`{团队规模}`、`{交付量}`、`{准确率 / 返修率}` |
| Dify 工作流自动化 | `{公司 / 项目方}`、`{起止时间}`、`{我的角色}`、`{处理量}`、`{节省工时 / 响应时间}` |
| 项目经理助理（海天瑞声） | `{起止时间}`、`{项目背景}`、`{项目数 / 交付量}` |

第四个项目是可选的。不想展示就从 `projects` 数组里删掉这一项。

## 3. 视频评测主案例

文件：`app/data/video-case.ts`
页面：`/cases/video-model-comparison/`

### 3.1 要生成的视频

四个模型各一条，文生视频和图生视频各做一组，共 8 条。页面的对比墙默认放 4 条（每个模型选一组），另一组可以用在 Bad Case 截帧里。

| 项 | 要求 |
|---|---|
| 格式 | H.264 MP4 |
| 分辨率 | 720p（1280×720），16:9 |
| 时长 | 5 秒左右，四个模型保持一致 |
| 大小 | 单个 ≤ 5MB |
| 存放位置 | `public/videos/`，例如 `public/videos/model-a.mp4` |
| 封面图 | 每条视频截第一帧，存到 `public/videos/posters/`，WebP 或 JPG，1280×720 |

填写时路径写成 `/videos/model-a.mp4` 这种以 `/` 开头的形式。

### 3.2 建议的 Prompt

下面是建议，你可以按自己的测试目标改。关键是四个模型用同一份 Prompt 和同一张首帧。

**核心任务**（建议）：人物从看向窗外转为低头看手里的信，转头动作连贯，身份特征不变。这个任务同时考验人物一致性、动作连续性和指令遵循，失败时容易截到有代表性的帧。

**文生视频 Prompt**（建议）

```
Medium shot, locked camera. A woman in her late 20s with a chin-length straight black bob,
a blue rectangular hair clip on her right side, coral triangular earrings, and a
mustard-yellow cardigan over an ivory shirt sits on the edge of a bed in a pale-blue bedroom.
Soft morning light comes from a window on the left. She looks out the window, then slowly
lowers her head to read a handwritten letter in her hands. One continuous motion, natural
speed, no cut. Cinematic realism, 16:9.
```

**图生视频**：首帧用 `app/assets/generated/she-forgets-yesterday-frame-01-v2.webp`（已有的晨光卧室画面），Prompt 只写动作：

```
She looks out the window, then slowly lowers her head to read a handwritten letter in her
hands. Locked camera, one continuous motion, natural speed. Keep her face, hair clip,
earrings and cardigan unchanged.
```

**生成参数建议**

| 项 | 建议 |
|---|---|
| 每个模型的生成次数 | 至少 3 次，全部保留，不要只留最好的一条 |
| 展示哪一条 | 事先定好规则，例如“展示第一次生成的结果”，并写进任务卡 |
| 随机种子 | 能固定就固定并记录 |
| 记录项 | 模型名与版本、生成日期、所有可见参数、Prompt 原文 |

### 3.3 生成之后要填的内容

| 字段 | 填什么 |
|---|---|
| `taskCard` | 评测目标、四个模型的名称与版本、生成日期、时长、分辨率、样本数 N |
| `contract` | 核心任务、镜头要求、允许偏差、关键失败（身份锚点已预填） |
| `prompt` | 实际使用的 Prompt 原文 |
| `models` | 每个模型的名称、视频路径、封面路径、严重度结论（`PASS` / `MINOR` / `MAJOR` / `CRITICAL`） |
| `scores` | 8 个维度 × 4 个模型，每格 1–5 分加一句证据（写时间码和看到的事实） |
| `badCases` | 3–5 条：截帧路径、模型、时间码、失败类型、可见现象、原因假设、复测设计 |
| `conclusions` | 每个模型适合什么场景 |
| `findings` | 可复现的发现，1–3 条 |
| `sampleSize` | 样本数 |

失败类型从文件底部的 `failureTypes` 十类里选。

### 3.4 Bad Case 截帧

| 项 | 要求 |
|---|---|
| 数量 | 3–5 张 |
| 尺寸 | 1280×720，WebP 或 JPG |
| 标注 | 在图上圈出问题位置再导出 |
| 存放位置 | `public/videos/badcases/`，路径写成 `/videos/badcases/01.webp` |

## 6. 发布前检查

1. 全局搜索 `{`，确认 `app/data/profile.ts` 和 `app/data/video-case.ts` 里没有剩余占位符。
2. 运行 `npm run verify:release`，全部通过。
3. 运行 `npm run acceptance`，确认“含 video 标签的页面”里出现了主案例页。
4. 把 `redesign/portfolio` 合并到 `main` 并推送，GitHub Actions 会自动部署。
